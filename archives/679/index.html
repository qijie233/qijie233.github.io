Why I Gave Up Ubuntu + KDE + i3wm for Manjaro + i3wm

Qijie
2024-06-22
Tech Notes
Linux

Why

First: KDE is bloated and eats performance. On my old clunker, on a Raspberry Pi, and on other low-end devices it’s a burden, and its built-in animation effects don’t fit my principles (they feel sluggish). The steps to replace kwin_x11 with i3wm are fairly complicated, and some KDE components don’t cooperate well with i3wm — some can’t be used at all.

Second: I wanted to get away from Snap, the disgusting thing in Ubuntu (the distro I used before). It’s tightly coupled with Ubuntu, its mirror is only the official foreign server, which crawls for people here, and part of what apt installs is starting to be handed over to Snap — chromium, for example. So when is Snap going to die? (annoyed)

Third: if apt uses third-party packages built by users, you have to add PPA sources (the official repos may have old versions, or may not offer the package you want), and that drags in a whole series of compatibility and dependency problems. PPA sources can even interfere with system updates, which is the most lethal thing of all for system stability (spend two and a half days tearing dependencies apart by hand, and your data may end up served cold).

Fourth: if I went with Arch Linux instead, configuring everything from scratch would be a big time sink. Also, the once-a-day sudo pacman -Syu can only be done at noon, because sooner or later the rolling release will break (doge).

Fifth: in Kali Linux, the Nvidia driver that comes with the apt repo is incompatible with older graphics cards, and a system update can pull one thread and move the whole body, dragging in the kernel and the drivers — and for old hardware that can be extremely fatal (wrong resolution, or even a black-screen warning).

Sixth: packages like wine in the repos of Ubuntu and similar distros lag behind on updates, which may not suit someone as eager for the new features I need as me (I don’t want to wait).

How I dealt with it

You’re right, but Manjaro is a open-world adventure game Linux distribution based on Arch Linux. The game takes place in a fantasy world called the “desktop environment”, where those chosen by pacman are granted yay and channel the power of the AUR. You will play a mysterious character named [your username], encounter files of all kinds with all kinds of traits in /, and together with them defeat Panic and recover the lost Config — while gradually uncovering the truth of “the rolling release breaking”.

Advantages

The desktop environment can be pre-selected: common DE/WMs such as i3wm, KDE, and Gnome

The update style is very, maybe even nine-tenths, Mo Qingxian (half a beat slow, for the sake of stability)

Note

You must not casually swap the Manjaro repos for the Arch ones, otherwise there is a fixed 100% probability that the rolling release will break.

yay

I can call this thing a godsend. When the official Manjaro/Arch repos don’t have the package you want, you can go look in the AUR (the community third-party package repo). Take the linuxqq package: Tencent doesn’t officially support Arch-based distros, so other users unpack the deb package and repackage it into the pkg format that Arch systems use, then throw it into the AUR so other users can install it (or build the package manually through the PKGBUILD).

In practice you only need it when pacman can’t get something. It’s not recommended, and there’s no need to add sudo (it’s added automatically during installation, so you don’t need to worry about it yourself).
