为什么我放弃了Ubuntu+KDE+i3wm而选择了Manjaro+i3wm

祈杰喵
2024-06-22
技术笔记
Linux

原因

其一：KDE 臃肿吃性能，对自己的老爷机和树莓派等低端设备来说是一个累赘，并且自带的动画效果不符合自己的原则（有拖泥带水的感觉），把kwin_x11替换为i3wm的步骤较为复杂以及KDE的一些组件不能很好的跟i3wm配合甚至无法使用

其二：自己想摆脱Ubuntu（原先使用的发行版）那恶心人的Snap（与Ubuntu高度耦合且镜像服务器只有对国内来说龟速的国外官方服，并且apt安装的一部分东西开始交给Snap了，例如chromium），所以说Snap什么时候死啊（恼）

其三：apt 如果使用用户构建的第三方包，就要通过添加PPA源的方式（官方源软件版本可能较为老旧或者不提供自己想要的软件包），那么会引入一系列的兼容以及依赖问题，甚至PPA源还会干涉系统更新，这一点对于系统稳定性来说是最为致命的（手撕依赖两天半，搞不好数据凉拌）

其四：如果自己选用Arch Linux的话，那么一切从零开始配置是一个很吃时间的大事。另外，每天一遍的 sudo pacman -Syu只能中午做，因为早晚会滚挂(doge)

其五：Kali Linux 中apt源自带的N卡驱动不兼容较老的显卡，并且系统更新可能会牵一发而动全身，波及内核与驱动，而这一点可能对老旧设备来说是极其致命的（分辨率不正常甚至黑屏警告）

其六：Ubuntu等发行版的源的wine等软件的更新较为滞后，对于急切追求需要的新功能的自己来说可能不适应（不想等）

应对

你说得对，但是Manjaro是基于Arch Linux的开放世界冒险游戏Linux发行版，游戏发生在一个被称作“桌面环境”的幻想世界，在这里，被 pacman 选中的人将被授予 yay，导引 AUR 之力。你将扮演一位名为 [你的用户名] 的神秘角色，在 / 中邂逅类型各异、特性不同的文件们，和它们一起击败Panic，找回失散的Config——同时，逐步发掘“滚挂”的真相。

优势

桌面环境可以预选i3wm、KDE、Gnome等常见的DE/WM

更新风格十分甚至九分的墨清弦（慢半拍，为了稳定）

注意

Manjaro源不能擅自换为Arch源，否则有100%固定概率滚挂。

yay

这个玩意我可以称之为神器，当Manjaro/Arch官方源没有自己想要的软件包时，可以找一找AUR（用户第三方包源），例如 linuxqq 这个包，tx没有对Arch系发行版进行官方支持，其他用户就拆解deb包等重新封包为适用于Arch系的pkg格式并丢进AUR方便其他用户安装（或者是通过PKGBUILD手动构建包）

实际上只有pacman下不到的时候才用到它，不推荐也不用加sudo（安装时会自动加，不需要你自己操心）
