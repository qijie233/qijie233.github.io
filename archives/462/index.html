Proxy Intro

Once you’ve set up a proxy server, the data packets you send go through the proxy server to the corresponding port on the actual server, and then the requested data comes back to you. Basically a middleman skimming the margin (lol). It’s usually used to access things that can’t be reached from within a region (as a stepping stone and so on).

Legality: for those of you in China, the broadband you connect through belongs to one of the three big domestic carriers, and without a carrier’s broadband a proxy alone can’t get you online — which is enough to refute most of the fallacies out there (refute? normally you don’t even get the chance??).

Note: the server the proxy runs on can see the data you request (under https, only the domain and IP). For safety, please don’t connect to proxy servers of unknown origin.

It can temporarily change your IP (which is exceptionally useful in some cases). These days the proxy protocols include the following (not exhaustive):

  • http, the classic proxy protocol that works anywhere, but its security is about the same as running around naked. TLS came along later, but TLS sacrifices a good chunk of cross-platform compatibility in exchange for security — and it doesn’t support UDP.
  • socks4/5 (socks 4/5), a more complete proxy protocol. Its security is the same as http’s, but it does support UDP.
  • ssh: besides remote terminals and remote file transfer, it’s also an excellent secure proxy for *nix systems, though its stability as a proxy isn’t great nowadays.
  • Suansuanru | Toujuan | Weierwei and so on, which add obfuscation and other features to improve security; this article won’t introduce them or explain them.

Whatever they call a “ladder”, it’s fundamentally still a proxy server.

As for http proxies, the most famous one is the squid server.
